3. Configuration Catalog

Configurations come from binary catalogs, one per (N,M) and geminal-width set, in <PSIDATADIR>/reks_catalog (a non-empty environment variable PSI4_REKS_CATALOG replaces the directory). A catalog lists every spin-inequivalent configuration of every spin manifold, each with a name and a type. Installed:

reks reks_geminal_widths Catalog 2S
[2, 2] — reks22 0, 2
[2, 3] [3] reks23_u3 0, 2
[2, 4] [4] reks24_u4 0, 2
[4, 4] — reks44 0, 2, 4
[4, 5] [2, 3] reks45_u23 0, 2, 4
[4, 6] [3, 3] reks46_u33 0, 2, 4
[6, 6] — reks66 0, 2, 4, 6

Any other (N,M), or (4,5)/(4,6) without REKS_GEMINAL_WIDTHS, stops the run at catalog load (Active space fails to load).

REKS_GEMINAL_WIDTHS

Type
array
Default
[] (all 2)
"reks": [4, 5],
"reks_geminal_widths": [2, 3],
  • Orbital count of each two-electron geminal: N/2 integers, each in [2, 8], summing to M. Empty (default): every geminal spans 2 orbitals.
  • A width-w geminal holds 2 electrons in w orbitals; its configurations carry orbital-letter suffixes (OSSa1, DESb1).
  • Selects the catalog reks{N}{M}_u{w0}{w1}…; the installed ones are listed above.

Naming convention

Every configuration has a name of the form <TYPE><index>, e.g. PPS1, OSS2, T_PPS3; a member of a spin-polarized set is named <TYPE>_<k>, e.g. DOSS_SPS_0, TT_SPS_0. A type is a _-separated sequence of words; a multiplier letter in front of OSS or DES counts the geminals (none = 1, D = 2, T = 3; the generator naming continues with Q, Qu, S, Sp, O, N for 4–9, which no installed catalog uses).

Prefix family Meaning
PPS The perfectly-paired singlet: every geminal Φ0. Every (N,M) catalog has at least one PPS configuration.
OSS, DOSS, TOSS 1, 2, 3 open-shell-singlet (Φ1) geminals. Installed: OSS in every catalog, DOSS in (6,6), TOSS only as TOSS_SPS in (6,6).
DES, DDES, TDES 1, 2, 3 doubly-excited (Φ2) geminals. TDES exists in (6,6) only.
Compound types (OSS_DES, DOSS_DES, OSS_DDES) Both kinds of geminals in one configuration.
k leading T (T_PPS3, TT_SPS_0, TTT_SPS_0) k triplet-coupled geminals; manifold 2S = 2k (coupling: §2). In (2,2) the single 2S = 2 configuration is named T1.
SPS (as in DOSS_SPS_0) A spin-polarized configuration; member k of the set is orthogonalized to members 0 … k − 1.
Lettered types (OSSa, DESb, Ta, DESa_OSSb, TaTb_SPS) Generalized-geminal catalogs (REKS_GEMINAL_WIDTHS).

Bulk tokens (§5) select configurations without listing names; an unknown token lists every valid type and name of the block's manifold (Unknown configuration name or type).

FON sets

The FON set of a configuration (column FON set of the SI pool tables) follows its generation, the number of open pairs (§2).

Set Generation (open pairs) Configuration types
n 0 PPS, DES, DDES, TDES
m 1 OSS, OSS_DES, OSS_DDES
u 2 DOSS, DOSS_DES
v, w, x, y, z 3–7 —

The label is the set letter, the pairing-scheme digit (n0, n1), and tK for run sector K > 0 (m0t1), sector 0 being the lowest 2S of the run. Spin-polarized configurations, whose pairs are all open, have no FON and show -.

Pairing schemes

A scheme (numbered from 0) is one pairing of the M active orbitals into geminals (§2). No option selects it; the configurations of the SA pool do (single-scheme:N, mixed-scheme:N, §5). The setup report prints the schemes:

=> Pairing schemes (GVB(2,2) geminal pairs) <=

   Scheme 0: (a,d) & (b,c)
   Scheme 1: (a,c) & (b,d)

[...]
   FON = fractional occupation number n_p of an active orbital (0..2, n_p + n_q = 2 in a pair).

4. Selecting Configurations

Active space

REKS

Type
[N, M]
Default
— (required)
"reks": [4, 4],
REKS requires the canonical symmetric-Ms reference: N=2 implies molecule multiplicity 1 (even N -> 1, odd N -> 2), but the molecule multiplicity is 3. Do not set the multiplicity to 2S+1; keep the canonical value and pick spin manifolds via SA_REKS_2SPIN / SI_REKS_2SPIN.
  • N active electrons in M active orbitals, exactly two integers; a third element (the former spin element) is an input error. Only installed catalogs run (§3).
  • Molecule multiplicity: 1 for even N, 2 for odd N (no installed catalog has odd N); any other value is the error above. The spin manifolds are chosen by SA_REKS_2SPIN / SI_REKS_2SPIN or the ladder (§6).

SA pool

SA_REKS_CONFIGS

Type
array
Default
catalog sa_default pool on 2S = 0
Alias
REKS_SA_CONFIGS
"sa_reks_configs": ["PPS1", "OSS1", "OSS2"],
=> SA pool <=

    Cat  Config       SA weight  Definition
   ---------------------------------------------------------------
      0  PPS1          0.333333  A[(core) Phi_0(a,d) * Phi_0(b,c)]
      1  OSS1          0.333333  A[(core) Phi_1(a,d) * Phi_0(b,c)]
      2  OSS2          0.333333  A[(core) Phi_0(a,d) * Phi_1(b,c)]
   ---------------------------------------------------------------
                 sum = 1.000000

   E[SA-REKS] = 0.333333 * E(PPS1)
              + 0.333333 * E(OSS1)
              + 0.333333 * E(OSS2)

   Cat = catalog index of the configuration. A[...] = antisymmetrized product
   of the geminals (pairing schemes above) and the doubly occupied core orbitals (core).
  • Flat list = one block on one spin manifold, e.g. ["PPS1", "OSS1", "OSS2"] or by local index [0, 1, 2]. Elements: configuration names, local integer indices, or bulk tokens (§5).
  • A configuration may not repeat within a block: an SA block is a weighted list (§5).
  • Nested list = one block per spin manifold, e.g. [["PPS1", "OSS1"], ["T_PPS1"]], mapped to manifolds by ladder position or by SA_REKS_2SPIN (§6).
  • Absent: the catalog's sa_default pool on 2S = 0. Defaults: REKS(2,2) [PPS1, OSS1], REKS(4,4) [PPS1, OSS1, OSS2], REKS(6,6) [PPS1, OSS1, OSS2, OSS3].
  • Check sum = 1.000000 and that every SA_REKS_EXTRA determinant of the input is listed (Extra1, …).
See
SA_REKS_WEIGHTS, SA_REKS_EXTRA, §2

SA_REKS_WEIGHTS

Type
array
Default
uniform 1/n
Alias
REKS_SA_WEIGHTS
"sa_reks_weights": [0.5, 0.25, 0.25],
  • One non-negative weight per SA pool entry, in the order typed (concatenated block order, then the SA_REKS_EXTRA determinants), summing to 1.0 (tolerance 10-8). Omitted: uniform 1/n.
  • A configuration or extra determinant with weight 0 leaves the SA ensemble; a zero-weight configuration that is also an SI member has its SI-only geminals' FONs optimized after the SCF.
  • If SA_REKS_2SPIN lists manifolds out of ascending-2S order, configurations and weights are re-sorted jointly into ascending 2S; a weight still matches the configuration in the order typed.

SA_REKS_EXTRA

Type
array of arrays
Default
none
Alias
REKS_SA_EXTRA
"sa_reks_extra": [[1, 1, 1, 1, 0, 0, 0, 0]],
=> SA pool <=

    Cat  Config       SA weight  Definition
   --------------------------------------------------------
      0  PPS1          0.250000  A[Phi_0(a,d) * Phi_0(b,c)]
      1  OSS1          0.250000  A[Phi_1(a,d) * Phi_0(b,c)]
      2  OSS2          0.250000  A[Phi_0(a,d) * Phi_1(b,c)]
         Extra1        0.250000  A[|a,b,c,d|]
   --------------------------------------------------------
                 sum = 1.000000
  • Each element is a Slater determinant given as an occupation vector [alpha(M) | beta(M)] of length 2M, 0/1 entries summing to N; the call above is the all-α determinant of REKS(4,4).
  • Each determinant joins the SA ensemble with a fixed weight from the tail of SA_REKS_WEIGHTS, adds its Kohn–Sham energy to ESA, carries no FON, and changes the SA orbitals and with them every SI state. It never enters an SI cassette.

Gradients, couplings, relaxed properties

Computed from one coupled-perturbed REKS (CP-REKS, Z-vector) solve. List-of-lists options mirror SI_REKS_CONFIGS: inner list e refers to cassette e; roots are 0-based and sorted by energy.

SI_REKS_GRAD

Type
array of arrays
Default
[] (SA ensemble)
"si_reks_grad": [[1, 2], []],
=> Gradient request <=

   Cassette  States    NAC pairs
   -----------------------------
          0  S1 *, S2  S1/S2
   -----------------------------
   States = SI states whose nuclear gradient is computed. * = followed state, returned by gradient().
  • Roots whose gradients are computed, one inner list per cassette (inner list e = cassette e); roots are 0-based and sorted by energy. Inner list [-1] = all roots of that cassette ([[-1]]); a flat [-1] is an input error.
  • The followed root, marked * in Gradient request, is the first entry of the first non-empty inner list (-1 → root 0). Without SI_REKS_GRAD it is the lowest root of the first cassette with SI_REKS_NAC pairs.
  • With a followed root, CURRENT ENERGY is its energy, also stored as REKS TARGET STATE ENERGY, in energy() and gradient(); gradient() returns its gradient (Nuclear gradients of SSR states). Without SI_REKS_GRAD and SI_REKS_NAC, CURRENT ENERGY = SCF TOTAL ENERGY. SCF TOTAL ENERGY is always ESA, plus Epen with REKS_DELOC_IPR_PENALTY.
  • CURRENT DIPOLE is the relaxed dipole of the followed root when SI_REKS_PROPERTY_FOR lists that root, and is unset otherwise.
  • Triplet gradient of reks [2, 2]: the triplet-gradient worked input (§1), with si_reks_grad [[], [0]] following T1 of cassette 1.

5. Bulk Tokens and Pattern Syntax

Accepted wherever a configuration name is (SA blocks, SI cassettes, exclude:):

Token Expands to
"full" The entire configuration block of that manifold.
A configuration type name, e.g. "PPS", "OSS", "DOSS" Every configuration of that type in the manifold, lettered types (OSSa, Ta) included.
"single-scheme:N" (PSithon: "single-scheme-N" or "single-scheme_N") Every configuration of pairing scheme N (0 if :N is omitted), plus the spin-polarized base configurations, which all schemes share.
"mixed-scheme:N" The SSR state set on scheme N: that scheme's single-excitation configurations (at most one Φ1 or Φ2 geminal) plus every open-shell-singlet configuration of the manifold plus the spin-polarized base configurations. For REKS(4,4), mixed-scheme:0 = PPS1, OSS1, OSS2, OSS3, OSS4, DES1, DES2, DOSS_SPS_0, DOSS_SPS_1.
"sps" The spin-polarized base configurations.
A pattern with * or ? Every configuration name it glob-matches.
"exclude:X" (also exclude-X / exclude_X) SI cassettes only. Removes what X (any form above) selects from the cassette, wherever it stands in the list, e.g. ["full", "exclude:sps"] = the whole manifold minus the spin-polarized base.

A scheme token may union several indices: "single-scheme-1-2-3", or "single-scheme:1,2,3" in the Python API; a literal : cannot be used inside a PSithon .dat array element, since the PSithon array parser splits on :. The separators :, -, _ and , are equivalent; a scheme reached twice is an input error. Tokens are case-insensitive. Besides indices, a scheme token accepts scheme classes, defined for two-orbital geminals relative to scheme 0 by the permutation of antibonding partners: T (one transposition), D<k> (k disjoint transpositions, k ≥ 2), C<l>[X<l>…] (cycles of the listed lengths, each ≥ 2), e.g. "single-scheme-T".

6. Spin Manifolds (2S) and Multi-Sector Runs

The sectors of a run are the spin manifolds (2S) used by any SA block or SI group, in ascending 2S. All sectors share one SCF. Without SA_REKS_CONFIGS the SA ensemble is the default 2S = 0 pool, which has no high-spin configuration; patterns below add the all-α determinant with SA_REKS_EXTRA.

Mode When Block or group i Empty block []
Ladder SA_REKS_2SPIN / SI_REKS_2SPIN absent the i-th manifold of the catalog, ascending 2S (0-based, order typed) skips that rung
Explicit SA_REKS_2SPIN / SI_REKS_2SPIN given the manifold named by entry i declares the manifold: it participates with no configurations
